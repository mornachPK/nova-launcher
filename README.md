# COBBLEMON NOVA

노바 서버용 Windows 설치·업데이트 런처 개발 저장소입니다.

> **개발 준비본입니다. 아직 플레이 가능한 설치본이나 공개 다운로드 릴리스가 없습니다.**

## 목표
디스코드 승인 → 다운로드 채널 열기 → 본인 Minecraft 계정 로그인 → 모드팩 설치 → 업데이트 확인 → 서버 접속.

## 현재 상태
- Modrinth를 사용하는 최초 가져오기 및 실행 연결 코드를 준비했습니다.
- 관리 대상 파일만 다운로드·검증·백업·갱신하는 엔진을 작성했습니다.
- Windows PowerShell 5.1의 격리된 테스트에서 25개 검사가 통과했습니다.
- 실제 새 PC에서 전체 설치·업데이트·접속 검증은 아직 하지 않았습니다.
- 모드/리소스 228개 중 200개는 공식 동일 파일 다운로드 주소를 확인했습니다. 나머지 28개와 클라이언트 설정·자산은 배포 출처/조건을 검토 중입니다.
- 배포용 mrpack, 공개 게임 서버 주소, HTTPS 업데이트 피드가 아직 확정되지 않았습니다.

## 파일
- `Nova.cmd`: Windows 실행 진입점
- `Nova.ps1`: 처음 설치 안내, 인스턴스 등록, 업데이트 후 실행
- `Nova.Core.ps1`: 경로 검증, 다운로드 해시 검증, 백업 및 실패 복구
- `distribution.json`: 배포 준비가 끝나기 전까지 `enabled: false` 유지
- `DISCORD-SETUP.md`: 인증 역할과 다운로드 채널 설정안

## 보호 범위와 제한
로그인은 Modrinth가 처리합니다. 비밀번호나 토큰을 이 저장소 또는 런처에 입력하지 않습니다. 월드·개인 지도·계정·기존 사용자 설정은 배포하지 않습니다.

처음 설치 시 Modrinth 설치 확인과 새 NOVA 모드팩 바로가기/폴더 등록 단계가 필요합니다. 이후 등록된 파일의 업데이트를 자동 처리하도록 설계했으며, 완전 무인 최초 설치를 구현한 상태는 아닙니다.

관리 파일에 개인 수정이 있으면 덮어쓰지 않고 중단합니다. 강제 종료 흔적이 있으면 실행을 차단하며 기록된 백업으로 수동 복구가 필요합니다. Java 실행 중에는 업데이트가 차단됩니다. HTTPS 배포 저장소를 신뢰하는 방식이며 별도 파일 서명 시스템은 아직 없습니다.

다운로드 채널 권한과 게임 접속 권한은 별개입니다. 실제 게임 접속은 온라인 인증 및 화이트리스트로 제한합니다. 공개 다운로드 링크가 전달되는 것 자체를 막는 인증 서비스는 포함하지 않습니다.

## 다음 단계
1. 누락된 배포 출처와 필요한 클라이언트 설정 검토
2. 완전한 mrpack 설치본 생성
3. 공개 서버 주소 및 업데이트 피드 구성
4. 새 인스턴스에서 최초 설치·갱신·실패 복구·접속 검증
5. 검증한 릴리스만 디스코드 다운로드 채널에 안내

기반 모드와 리소스의 권리는 각 제작자에게 있습니다. 이 저장소에는 모드 바이너리, 타사 리소스, 월드 또는 계정 정보를 포함하지 않습니다.
